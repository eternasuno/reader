# UI (`web/`)

## Layout & Focus

- **Responsive panels** (pure CSS breakpoints, never JS media queries): wide = 3 columns (`sidebar | list | reader`); medium = `sidebar | (list or reader)`; narrow = single active panel, with the drawer toggle inside the list heading (no separate top bar). Desktop (`md+`) sidebar collapse state persists in `localStorage` (`reader.sidebarCollapsed`), collapsing the sidebar grid track to `0rem` while keeping the panel mounted with `inert`/`aria-hidden` and fixed inner `min-w-*` so `grid-template-columns` animates without text reflow; below `md`, the drawer and backdrop stay mounted and transition via `max-md:` transform/opacity classes. Narrow icon buttons use `max-md:size-10`; touch devices get a global scale from `html { font-size: 112.5% }` under `@media (pointer: coarse)` in `index.css`, so sizes must stay `rem`-based (`Icon` sets its width/height in `rem`) and controls never carry per-element `pointer-coarse:size-*` enlargement; `pointer-coarse:` is only for touch-only affordances (e.g. the always-visible read circle); root containers pad `env(safe-area-inset-*)` (`viewport-fit=cover`); dialogs become bottom sheets and toasts span the bottom below `sm`. Icon's svg always carries `inline-block`, so responsive show/hide classes go on a wrapping element, never on `<Icon>` itself. When CSS hides a panel containing `document.activeElement`, move focus to the visible panel based on actual element visibility (computed `display`/`visibility` and `inert` ancestors).
- **Article list**: virtualized via a thin Solid 2 `VirtualList` wrapper around framework-agnostic `@tanstack/virtual-core` (using `onSettled` + `createEffect` to measure row heights after mount and auto-scroll when `activeIndex` changes). In all and folder scopes, render the feed separator inside the measured wrapper for the first ID of each contiguous feed run, above the card or skeleton. Read the title and icon reactively from the feeds store (`LIB-GROUP-1`). The list heading is a single compact row (title + plain count left, icon actions right) whose height matches the reader toolbar (`min-h-13`).
- **Reader**: switching articles resets the reader scroll container to the top (`scrollTop = 0`), while scrolling adds toolbar elevation shadow.
- **Motion**: one motion system in `@theme` of `index.css`. App animations are applied directly, with no `prefers-reduced-motion` media queries or `motion-safe:`/`motion-reduce:` variants (daisyUI's built-in component CSS is left as shipped). All motion uses `--ease-standard` (`ease-standard`, also the default transition timing). State feedback (hover, color, chevron rotation) uses the default `150ms` transition. Movement and entrances take `200ms`: drawer slide, sidebar collapse, `animate-fade-in` (4px rise and fade) on article cards, the reader article (keyed by article id so each switch replays it), and expanded folder children; `animate-fade` on dialog backdrops; `animate-dialog-in` on centered dialogs and `animate-sheet-in` on narrow-screen bottom sheets; `animate-toast-in` on toasts. Menus use `animate-pop-in` (`150ms`, scale and fade only, since anchor fallbacks may flip them). Mounted-on-demand surfaces animate in only; they unmount instantly. List membership changes (`LIB-LIVE-1` live replacements, the in-place mark-all/unsubscribe reload `reloadScopeInPlace`, saved-page removal, and folder moves, all via `changeRows` in `state/library-motion.ts`, which animates only when the visible rows change) go through `runListTransition` (`ui/listTransition.ts`): a same-document view transition whose update callback commits the change and waits two macrotasks so virtual rows mount, measure, and restore the viewport anchor before the new state is captured. The page root is never captured (`:root { view-transition-name: none }`); only rows inside the registered list area (the `ArticleListPane` content wrapper, which stays mounted while the list empties and refills; scrolling is observed with a capture listener) get `view-transition-name: row-<id>` while `data-list-transition` is set, and `::view-transition` is clipped to the list rect because transition groups ignore ancestor `overflow` clipping. Callers recheck staleness guards inside the update, since the old state is captured first; a folder move sends its request immediately but settles (and rolls back) only after its optimistic update has run, so the deferred update never overwrites a rollback. Rows mounted during the update skip their own `animate-fade-in`. Firefox screenshots do not render the transition overlay; verify with `document.getAnimations()` on `::view-transition-*` pseudo-elements. Content loading always uses daisyUI `skeleton` placeholders shaped like the content they replace (article cards `ArticleRowSkeleton`/`ArticleListLoading`, reader `ReaderSkeleton`, session check `AppSkeleton` and the login card skeleton), each wrapped in `role="status"` with an accessible name; never a centered spinner. Spinners remain only as in-place progress for an action (`Button` `loading`, the sidebar mark-all indicator) and the extract icon pulses while extracting. Do not mix other durations or easing keywords (`ease-out`, `duration-300`, …). Library scopes are children of one pathless layout route that renders the guarded `LibraryPage` (children render nothing), so switching scope never remounts it or re-verifies the session.
- **Menus & drawers**: list/row/reader menus use in-menu sub-panels (`MenuItem submenu keepOpen`, a back header, then items): `FeedMoveSubpanel` for `移动到`, `FeedReaderModeSubpanel` for a feed's `缺省视图` (feed row, single-feed list, and reader menus), and the reader `视图选项` panel. `ListOrderCheckbox` renders `从旧到新` only in sidebar feed menus and the single-feed list menu. It reads the feed’s stored order and saves via `PUT /api/feeds/:id/order`. Do not reintroduce a feed options drawer, a stored embedded reader mode, a manual refresh item, summary-line/new-tab list options, thumbnails, or an end-of-article next card.
- **Solid 2 writes are batched**: after `setX(...)`, call `flush()` before code that immediately reads `x()`.
- **Selection & rows**: selected sidebar rows and article cards use `bg-neutral text-neutral-content`; hover uses `bg-base-200`. Content inside selectable rows dims with `opacity-*` (not `text-base-content/*`) so it inherits the selected text color. Counts are plain `text-xs tabular-nums opacity-60`, never badges. Article rows are `rounded-box` cards without dividers; group headings (sidebar `订阅源`, settings groups) use `text-xs font-semibold tracking-wider uppercase text-base-content/50`; dialogs have no header/footer dividers and use `btn-sm` actions; empty states use a 40px `opacity-30` icon + `text-base` title + `text-sm` hint; thumbnails and site icons (`SiteIcon`) render `loading="lazy" referrerpolicy="no-referrer"` and are keyed by URL so reused virtual rows retry after a failure.

## Visual System

- Tailwind CSS 4 + daisyUI 5 dark theme `blackwhite` (`color-scheme: dark`), plus custom `@theme` token `--color-brand: #d5a15c`:
  - `--color-base-100 / -200 / -300`: `#1e1e1e / #252525 / #343434`
  - `--color-base-content`: `#dddddf`
  - `--color-primary / -content`: `#c9afe9 / #20172b` (primary actions only)
  - `--color-secondary / -content`: `#3a3a3c / #e5e5e7` (muted secondary actions: retry, empty-state, settings actions)
  - `--color-error / -content`: `#f28b82 / #2b1110`
  - `--color-neutral / -content`: `#5e4774 / #f2eafa`
- Keep `index.css` strictly to `@import "tailwindcss"`, `@theme`, and daisyUI config (no `@apply` or component CSS). Shared primitives (`Button`, `Input`, `Dialog`, `MenuCheckbox`, `MenuRadio`, `Icon`, `VirtualList`, `SettingsGroup` / `SettingsRow` / `StatusBadge`) live in `web/src/ui/` and carry no domain imports.
- Disabled controls must stay legible: daisyUI's default disabled radio/checkbox `opacity: 0.2` is near-invisible on this theme, so use `disabled:opacity-100 disabled:border-base-content/30` on the input and `has-[:disabled]:` utilities on the label. Gated forms (e.g. the Kindle form without SMTP) show a hint plus a link to the section that unlocks them.

## Article Body (`ArticleBody`)

- Render server-sanitized article HTML directly via `innerHTML` (no iframe, no re-sanitizing, `CM-ART-2`). Before rendering, parse it with `DOMParser` and strip `class` (source Tailwind classes would match app utilities), `id` / `name` (collisions and DOM clobbering), and `style`; add `referrerpolicy="no-referrer"` to images and `tabindex` / `role="button"` / `aria-label` to unlinked `http(s)` images.
- The page CSP served with `index.html` (`script-src 'self'`, `style-src 'self' 'unsafe-inline'`, `img-src 'self' https: http: data:`, `media-src https: http:`, `frame-src https: http:`, `object-src 'none'`, `base-uri 'none'`) is the second defense layer; never add inline `<script>` to `index.html` (the theme bootstrap is `public/theme-init.js`). The page `Referrer-Policy` is `same-origin`, which hides the app URL from image hosts while keeping `Origin` on same-origin POSTs.
- Reader typography lives in `components/articleBody.css`, scoped under `.article-body` (an exception to the `index.css` rule above), reading font size, family, and line height from `--article-*` custom properties set on the container from `readerAppearance()`. Keep Latin fonts before CJK fonts (avoid bare `system-ui` fallback quirks on Linux, and full-width CJK glyphs for `’` / `“` in English text). The body has no horizontal padding so text aligns with the reader header.
- Image clicks and `Enter` / `Space` are delegated on the container and open `ImageLightbox`, which owns `Escape` and focus return.
- Keep the embedded external-page frame (`RD-WEBPAGE-1`, with `allow-same-origin`) as a separate component; never merge it with `ArticleBody`.
