# Reader Engineering

Product behavior lives in `reader-spec`; this skill defines the target Go + SQLite + SolidJS 2 architecture and pinned libraries.

Conditional files:
- Read [database.md](database.md) when modifying SQLite connections, migrations, schema, indexes, or repositories.
- Read [ui.md](ui.md) when modifying styling, layout, shared UI controls, focus handling, or article body rendering.
- Read [upstream-issues.md](upstream-issues.md) before upgrading dependencies or adopting Solid `action` / optimistic APIs.
- Read [deployment.md](deployment.md) when modifying `Dockerfile`, `go:embed` static serving, SPA fallback, or container build stages.

## Technology Choices

| Concern | Choice | Why |
| --- | --- | --- |
| Backend | Go `1.27+`, stdlib `net/http.ServeMux` | single static binary, low RAM (~20–50 MB), satisfies `modernc.org/sqlite@v1.62` & `gofeed@v1.5` floor |
| IDs | `github.com/google/uuid` (`uuid.NewV7`) | RFC 9562 UUIDv7 with built-in monotonic sequence counter |
| Database | SQLite via `modernc.org/sqlite` + `github.com/pressly/goose/v3` | pure Go (`CGO_ENABLED=0`), single file, tracked transactional migrations, no external DB process |
| Feed parsing | `github.com/mmcdole/gofeed` (`rss` / `atom` / `json` subparsers + `DetectFeedType`) | RSS/RDF, Atom, and JSON Feed in one library; format-specific parsers keep `FD-PARSE-*` exact |
| Readability | `codeberg.org/readeck/go-readability/v2` | Readability.js v0.6.0 compatible, faster & lower memory than archived `go-shiori/go-readability`, preserves Tailwind utility classes |
| HTML sanitizing | `golang.org/x/net/html` + `github.com/microcosm-cc/bluemonday` | relative `href`/`src` resolution, strict allowlist sanitization, link `target="_blank"` |
| Webpage fetch | Go `net/http` (default); optional Jina API or external CDP via `github.com/chromedp/chromedp` (`NewRemoteAllocator`) | zero-dependency fast path; heavy JS pages delegated only when an external endpoint is configured |
| Kindle EPUB & Mail | stdlib `archive/zip` + `image/{jpeg,png}` (EPUB 3) + `github.com/wneessen/go-mail` | in-memory EPUB assembly with stored `mimetype` zip entry and bounded-memory image downscaling (`<= 1200×1600`, JPEG quality 75); context-aware SMTP (`3m` timeout) with implicit TLS (`465`) & mandatory STARTTLS (`587`) |
| Frontend SPA | SolidJS 2 (`solid-js` `^2.0.3`, `@solidjs/web` `^2.0.3`), `@solidjs/router` `^2.0.1`, `@solid-primitives/i18n` `3.0.0`, `@tanstack/virtual-core`; dev: `@solidjs/diagnostics` | async-in-graph reactivity, Solid 2 primitive i18n, thin custom wrapper over framework-agnostic `@tanstack/virtual-core` (avoids 1.x-only `@tanstack/solid-virtual` peer mismatch) |
| Styling & Build | Tailwind CSS 4 (`@tailwindcss/vite`), daisyUI 5, Vite 8/9 (`@solidjs/vite-plugin` `^3.0.1`), TypeScript, Biome, Vitest | native OXC Solid compiler (no Babel needed), zero runtime CSS-in-JS |

## Package Layout & Dependencies

```text
cmd/reader        ──> internal/http, internal/worker, internal/sqlite, internal/content, internal/fetcher, internal/epub, internal/mail, web (go:embed)
internal/http     ──> internal/domain, internal/worker
internal/worker   ──> internal/domain, internal/fetcher, internal/content, internal/epub, internal/mail
internal/sqlite   ──> internal/domain, internal/sqlite/migrations
internal/sqlite/migrations ──> database/sql + goose only (never internal/domain)
internal/content  ──> internal/domain
internal/fetcher  ──> internal/domain
internal/epub     ──> internal/domain
internal/mail     ──> internal/domain
internal/domain   ──> Go stdlib + github.com/google/uuid only
```

- `internal/domain` defines entities, value objects (`NormalizedURL`, `Retention`, `FolderName`), pure selection/retention logic, and repository/adapter interfaces. It imports no DB, HTTP, or UI libraries.
- Adapters never import each other or `internal/http`.

## Backend Architecture & Security Rules

- **Auth & CSRF**:
  - `POST /api/auth/login` hashes both the submitted password and `APP_PASSWORD` with `crypto/sha256` before calling `crypto/subtle.ConstantTimeCompare` (preventing length timing leaks), protected by per-IP rate limiting. Sets an HMAC-SHA256 signed `HttpOnly` cookie (`SameSite=Lax`, `Secure` when `APP_URL` is `https://`).
  - All state-changing `/api/*` endpoints (`POST`, `PUT`, `PATCH`, `DELETE`) verify `Origin` (falling back to `Referer` **only** when `Origin` is absent; rejecting missing, `"null"`, or malformed headers with `403`). Parse the header and `APP_URL` with `net/url` and require exact equality of lowercase `Scheme`, lowercase `Hostname()`, and effective port (`80`/`443` defaults normalized).
- **Known limitations**: the login rate limiter keys on `RemoteAddr` and ignores `X-Forwarded-For`, so behind a reverse proxy all clients share one bucket; the external CDP endpoint is not network-restricted (its operator must firewall it).
- **Dynamic external service config & job snapshots**: `internal/fetcher` reads the current `setting` row on each extraction, and `KindleSender` reads and **snapshots** the delivery + SMTP settings into the job when creating a `running` send — never cached at startup, and never mutated mid-delivery.
- **SSRF & Credential Boundaries**:
  - `internal/fetcher` wraps `net.Dialer.Control` so direct Go HTTP fetches (feeds, direct webpage extraction, EPUB images) resolve and reject loopback, private, link-local, and multicast IPs unless `ALLOW_PRIVATE_NETWORK=true`. Redirects re-run the dial-time check; hard timeouts (`15s`–`30s`) and body size caps (`10 MiB`) always apply.
  - External CDP (`BrowserEndpoint`, which itself may point to a private/Docker service) and Jina execute remote page/subresource fetches outside Go's dialer (`CM-FETCH-2`). Strip `user:pass@` URL credentials from API responses, OPML exports, and logs, and refuse (`422 WebpageFetcherError`) to forward credentialed URLs to `jina` or `browser` (`CM-URL-5`).
- **Secrets**: `JinaKey`, `BrowserEndpoint`, `SMTPPassword`, `APP_PASSWORD`, `SESSION_SECRET`, and URL credentials must never be returned in API responses or written to structured logs. Settings responses expose them only as `*Configured` booleans. Persisted SMTP errors (`kindle_send.error`) must not carry server text on AUTH failures (`smtp authentication failed (<code>)`), and must redact base64 (`Std`/`RawStd`/`URL`/`RawURL`) forms of the password and `AUTH PLAIN` blob, since servers may echo them. Whitespace-only secret input is treated as blank by both frontend and SQLite; non-blank secrets are stored untrimmed.
- **Workers**:
  - `RefreshQueue` keeps no in-memory queue or dedupe map: the database is the queue (`feed_schedule.next_refresh_at` plus `running` `feed_refresh` rows). Each of the bounded pool's workers (default `5`) claims the oldest due feed with no running attempt in one write transaction (`ClaimDueRefresh`), refreshes it, and finishes it in one transaction (`SucceedRefresh` / `FailRefresh`) that also sets the next due time (finish + `30` min) and the stored `updatedAt` / `failureCount` / `lastError` aggregates, so repeated failures (`failureCount >= 3`) surface in the UI (`FD-SCHED-*`). Idle workers wake on `Wake()` (HTTP handlers call it after `Create`, `ImportOPML`, or `RequestRefresh`; each successful claim wakes another worker) or a 1-minute poll; startup refreshes only overdue feeds. Fetch and parse failures are external and recorded as failed attempts. An internal database error releases the claim (`ReleaseRefresh`, bounded retry, then `OnFatal`), leaving the feed due and its aggregates unchanged; shutdown writes nothing, and startup `RecoverRunningRefreshes` marks leftover `running` rows `failed` (`interrupted`).
  - `KindleSender` acquires a per-process mutex/slot (`KindleSendInProgress` on conflict), persists the `running` `kindle_send` row with snapshotted delivery config, and **then** spawns the background worker using an application-owned `context.Context` (never `r.Context()`, which cancels when `202` is written). Startup marks any leftover `running` rows as `failed`. The next scheduled send time is stored in `kindle_schedule.next_send_at`; the scheduler checks immediately at startup and then every minute, and `ClaimDueSend` claims in one write transaction only when `next_send_at <= now`, delivery is configured, and no send is running (including the in-process slot). It inserts the `running` row and advances `next_send_at` to the next future occurrence in that transaction, and otherwise writes nothing so the send stays due (`KD-SCHED-1`). The scheduled EPUB date is the schedule-local date of the latest due occurrence snapshotted at claim (`ClaimedKindleSend.ScheduledFor`), never the worker clock; manual sends are undated.
- **Fail fast**: do not limp along on unexpected or unresolvable errors (worker goroutines do not `recover()`, except a panic while parsing an untrusted feed body, which becomes an external `FeedParserError`, as the HTTP extraction path already does). Persistent failure of the internal persistence layer (SQLite via domain repositories) in background code exits the process non-zero through the workers' `OnFatal` callback (`context.WithCancelCause` in `serveApp`), after a bounded retry or `3` consecutive failures (consecutive-failure counter); Docker restarts it. External failures (feed sites, SMTP, page fetches) and shutdown cancellation are never fatal. A missing `kindle_send` row (`ErrKindleSendNotFound`) is logged, not fatal. HTTP handlers return `500` for database errors instead of crashing the process. Graceful shutdown is hard-capped at `3s` in total (`shutdownTimeout`); unfinished work is abandoned.
- **Structured values as fields**: a value with internal structure is separate typed fields in every representation — SQLite columns, Go domain types, API JSON, and frontend state/drafts — never one formatted string parsed at each use (the Kindle schedule is `{ hour, minute, timezone }` / `send_hour` + `send_minute` + `timezone`, not `"08:30"`). Format strings only for display; opaque whole strings (URLs, IANA zone names, error text) stay single strings.
- **Static data vs task records**: entities and user-edited configuration (feeds, folders, settings) are kept apart from task records and runtime state (refresh attempts, send history, scheduler state) in Go types, API shapes, and SQLite tables; static records carry no runtime fields.
- **HTTP Errors**: handlers decode/validate request bodies once, map domain errors to `{ "error": "<ErrorCode>" }`, and keep internal causes in server logs only (`writeError` logs every 5xx cause sanitized, bounded, single-line; 4xx are not logged).

## Frontend Architecture (`web/`)

- **Solid 2 conventions**: `tsconfig.json` sets `"jsx": "preserve"` and `"jsxImportSource": "@solidjs/web"`; imports use `@solidjs/web` (`render`, `Portal`, JSX types) and `solid-js` (`createSignal`, `createMemo`, `createEffect`, `createStore`, `snapshot`, `onSettled`); routing uses `@solidjs/router` 2.0 `createRouter({ routes })` config objects with plain `<a>` elements and `useNavigate()`.
- **URL as source of truth**: active scope, open article ID, and the unread filter (on by default, `?all` turns it off) derive from router matches. `SessionGuard` protects all routes except `/login`; `/save?url=...` renders a confirmation form (never mutating on `GET`) and preserves validated relative `?next` across login attempts.
- **State**: one Solid store/signal module per concept (`feed`, `folder`, `savedPage`, `libraryList`, `reader`, `toast`, `settings`), communicating via exported accessors/actions. Entity records (library articles) live once by ID in a fine-grained `createStore`; every write is a draft mutation, and server snapshots merge with `reconcile(…, 'id')` so record identity survives reloads. Lists hold ordered IDs (`rowIds()`), never fresh record arrays, and `VirtualList` takes `keys` and renders each key's row exactly once (virtualizer `getItemKey` = row ID), so a field change only updates the bindings that read it; the active row is a `createProjection` map, not a per-row comparison. Quick actions never disable on in-flight state and roll back optimistically on failure, except mark-all, which is a pessimistic barrier. Read state runs through one serial ordered queue in `state/read-sync.ts` (entry registry and snapshot stamps in `read-sync-state.ts`; network calls and ambiguous-failure re-fetch in `read-sync-transport.ts`). Queue items are per-article read intents with an explicit `read` value, coalesced per article while queued, and opaque barriers (mark-all). Each intent segment runs to completion before the next item, so no article has two writes in flight. Each entry keeps `display` (latest intent, what the store shows) and `confirmed` (last server-confirmed value): a failure restores `confirmed` only when no newer intent is queued; an ambiguous failure also marks `confirmed` unknown (so a queued intent equal to the old value is still sent) and re-fetches the affected rows once after drain, dropping idle unknown entries for articles outside the store. A barrier freezes its scope predicate (`scopeMatcher`, folder membership included) when the write is sent; on `ok` it confirms covered entries read and patches idle rows without touching badges (the post-drain count refresh publishes totals), and stamps in-flight snapshots so a pre-barrier GET, judged by the incoming record's own kind/feed, cannot restore unread. A server snapshot overrides `confirmed` only if it was requested after the article's last settle and nothing is in flight. Sidebar count responses apply only when the queue was idle at dispatch and its mutation epoch is unchanged on return; otherwise a refresh runs on drain. Do not use Solid `action` / `createOptimistic` / `createOptimisticStore` for user mutations ([upstream-issues.md](upstream-issues.md)). After a save whose response omits server-derived fields (e.g. Kindle `nextSendAt`), re-fetch instead of keeping stale values. Forms with unsaved drafts guard every exit: `beforeunload` for reload/close and `useBeforeLeave` for in-app and `popstate` navigation.
- **API client & i18n**: `web/src/i18n/` defines typed `zh-CN` and `en` dictionaries (`type Dict = typeof zhDict`) wrapped via `@solid-primitives/i18n` (`createMemo(() => i18n.flatten(dicts[locale()]))` + `i18n.translator(dict, i18n.resolveTemplate)`), persisted in `localStorage` (`reader.locale`, `CM-I18N-1`). `web/src/api/` maps `<ErrorCode>` through the translator; only non-login `401 Unauthorized` triggers global redirect to `/login` (`401 InvalidCredentials` stays on the login form).

## Testing

- **`internal/domain`**: Go `testing` unit tests for URL normalization/credential redaction, OPML parsing/atomicity, feed selection/retention table cases, and Kindle 20 MiB splitting.
- **`internal/sqlite`**: repository contract tests against temporary-file SQLite (`t.TempDir()`, never `:memory:` for WAL/multi-pool tests) verifying keyset paging, `ON DELETE SET NULL` folder deletion, startup migration, foreign keys across pooled connections, and `EXPLAIN QUERY PLAN`.
- **`internal/content` & `internal/fetcher`**: parser rules (`FD-PARSE-*`), `bluemonday` sanitization, `go-readability/v2` extraction fixtures, and SSRF dialer blocking private IPs / redirects.
- **`internal/http`**: `httptest` coverage for SHA-256 constant-time auth cookie, login rate limit, parsed `Origin`/`Referer` CSRF check, async `202` Kindle enqueue + `409` recovery, and secret redaction.
- **`web/`**: Vitest in a client/DOM posture (`environment: 'jsdom'` or `'happy-dom'`, since `@solidjs/vite-plugin` 3.0 emits SSR/server code under explicit `environment: 'node'`) for reactive Solid 2 stores/effects (note: `useBeforeLeave` does not fire on `history.back()` under `memoryHistory()`; verify popstate guards in a browser after in-app navigation, since `navigate_page` entries exercise `beforeunload` instead) + manual browser checks for responsive 3-column layout, focus recovery, and article body typography.
