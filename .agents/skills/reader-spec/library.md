# The Library Screen

The single authenticated workspace: sidebar of scopes, virtualized article list, and reader pane.

## Rules

- `LIB-SCOPE-1`: Shows one scope at a time (`稍后阅读`, `全部订阅`, one folder, or one feed). Selecting the already-selected scope closes any open article without reloading the list.
- `LIB-LIST-1`: The accepted ordered ID snapshot defines the list (`CM-PAGE-1`). Fetch missing or stale records on demand for the rendered range (including overscan) plus 20 rows on each side, in batches of up to 200 IDs with one content request in flight. After it settles, continue with the latest requested window. Rows without cached content show skeleton cards. Remove IDs omitted by a successful response unless a newer record exists, then recompute the window. Keep at most 1,000 evictable records, evicting the farthest from the window first. The open article and records pinned by active read state or pending feed moves are outside that budget. An initial or reload snapshot failure shows a full-list error with `重试` to reload the snapshot. Live replacement follows `LIB-LIVE-1`. A window failure shows an inline alert with `重试` above the visible rows. That retry fetches content for the current window. Satisfying the current window clears the alert.
- `LIB-RELOAD-1`: Fetch a fresh snapshot when entering the library, switching scope, toggling the unread filter (`?all`), changing the active single feed’s `从旧到新` setting (`FD-PREF-1`), or `全部标记为已读` settling as described in `LIB-READ-2`. Ordinary single-feed reloads omit the `order` query and use the feed’s stored order. There is no manual refresh action for normal feeds, in any menu. Discard snapshot and content responses from earlier list loads. Entering the library or switching scope also refreshes sidebar feeds, folders, and unread counts. `LIB-LIVE-1` replaces the snapshot in place and supplies the boundary for the next active-scope mark-all click (`LIB-READ-2`).
- `LIB-LIVE-1` runs on each 60 s sidebar tick that passes its gates (`LIB-COUNT-2`) and when the page becomes visible. Fetch an ID snapshot for the active scope and unread filter only while the library is mounted and visible, an initial snapshot is accepted, no snapshot load or first-refresh wait (`FD-SUB-2`) is active, and the read queue is idle, including mark-all. Drop ticks while a live request is in flight. Discard the result if the library unmounted, the session cleared, the page is hidden, the queue is busy, or the list generation, membership revision, or read queue mutation epoch changed since dispatch. A failed ID request is silent and a later tick can retry. Replace the list in server order in place, keeping the generation, content cache, and loading state. Keep pending folder move overrides. A final move settlement or a confirmed deletion from the saved-page scope invalidates a live request already in flight. A live snapshot requested after a folder move settles uses the server’s membership for that feed. Always accept the new boundary, keeping the same keys when ID order is unchanged. Keep the first visible article at its viewport offset when it survives, use the virtual list's anchor fallback when it disappears, and stay at the top when already there. Refetch the current content window, including cached rows, to update read state from other devices. Pending local read intents continue to control their rows.
- `LIB-FILTER-1` keeps a newly read row visible immediately after marking it read. With the unread filter on, read rows disappear at the next reload or live replacement. An open article stays in the reader (`RD-NAV-1`).
- `LIB-READ-1`: Single read toggles, auto-read on open (`RD-READ-1`), and `将以上文章标为已读` share one serial read queue. Each intent carries an explicit `read` value. An uncached ID starts with an unknown prior state, so its intent is sent without an optimistic unread-count change. A record arriving during the write shows the latest intent. Intents for one article coalesce within a segment, and the queue skips an intent only when its value is already confirmed. An article never has two writes in flight. On failure, a row whose latest intent is still the failed value rolls back to its last known server state when available. The queue shows one error toast per segment when a change fails without being superseded. After drain, ambiguous failures and failures with an unknown rollback value refresh the current content window once if any affected record is cached. Cached records outside the window become stale. If the open reader article still needs recovery after that refresh, fetch its detail once. Drop idle unknown entries for IDs absent from the store.
- `LIB-READ-2`: `将以上文章标为已读` marks articles from the top of the active list through the last row intersecting the viewport. It includes uncached IDs and skips cached rows already displayed as read. With no intersecting row it does nothing. The queue sends ID batches of up to 200, with at most two in flight, and the post-drain sidebar refresh corrects unread counts. `全部标记为已读` calls the scope's own mark-all endpoint (`later.md`, `feeds.md`, `folders.md`) with a `before` UUIDv7 boundary and marks only rows at or below it; newer rows and their later toggles are unaffected. It is pessimistic: a barrier in the same queue that runs after earlier read intents and holds later ones until it settles. Nothing changes on screen until the server answers; while pending, the list heading and the scope's sidebar row show a spinner. Its boundary is taken at click time: the accepted snapshot's `boundary` when the marked scope is active and its snapshot is available, else the scope's last applied unread-count boundary, else the count endpoint is fetched when the barrier runs, without applying sidebar counts. A boundary-fetch failure or a definite request failure (HTTP error) shows one error toast and changes nothing. On success or an ambiguous failure (no HTTP response, no toast), the active list fetches a fresh snapshot whatever scope was marked (when a library page is mounted), the open article refreshes in place if it belongs to the marked scope (not reopened or auto-marked), and sidebar counts refresh once after the read queue drains (or once directly when no library page is mounted). After an ambiguous mark-all, later toggles on covered rows are sent rather than assumed already applied. Folder membership is evaluated when the read-all executes. If the session ends while a mark-all is pending, nothing more is sent and no toast or change happens. Neither button is ever disabled, and the `全部标记为已读` menu item is never disabled.
- `LIB-COUNT-1`: Sidebar hides zero unread counts; list heading always shows the count. Folder count = sum of its feeds' counts; `全部订阅` count = sum of all feeds' counts.
- `LIB-COUNT-2`: Sidebar unread counts (feed counts and saved-page count, each with its `boundary`) refresh on the existing sidebar triggers (`LIB-RELOAD-1` and mutations), after each read-queue drain, and every 60 s while the library is mounted. The 60 s timer is skipped while the read queue is non-empty, pauses while the page is hidden, and restarts after a refresh that applies counts. Becoming visible refreshes immediately. A count response applies only if the queue was idle when it was sent and no read or mark-all was enqueued before it returned; otherwise a refresh runs on drain. A count field changed locally during the request keeps its local value. Count refreshes never reload lists. Live replacement (`LIB-LIVE-1`) shares the periodic tick. Its cadence can stretch beyond 60 s when applied count refreshes restart the timer.
- `LIB-ROW-1`: Each row is a rounded card showing, left to right: an independent leading read-toggle control (`aria-pressed`; solid dot when unread, hollow circle on hover/focus when read), then source line (site icon + feed title for feed items / URL hostname for saved pages, relative publish time right-aligned when present, refreshing each wall-clock minute while the library is mounted, pausing while the page is hidden, and refreshing immediately when the page becomes visible; in `全部订阅` and folder lists the icon and feed title move to the group separator (`LIB-GROUP-1`), the line keeps only the publish time and is omitted when there is none; the single-feed list shows the feed title without icon), title (max 3 lines; bold when unread, dimmed when read), summary plain text (fixed max 3 lines, not configurable; no thumbnail). Feed icons (sidebar, rows, feed options) are the feed's own image (`iconUrl`: RSS channel `<image><url>`, Atom `icon` then `logo`, JSON Feed `favicon` then `icon`; absolute http(s) only, resolved against the feed URL, stored on refresh and returned as `iconUrl`), falling back to the `/favicon.ico` of the feed's site origin (`siteUrl`, `FD-PARSE-6`; never derived from the feed URL's host), then the RSS glyph (each step used when the previous is absent or fails to load); saved pages use the page origin's `/favicon.ico`, then a generic icon. Images load directly in the browser with `referrerpolicy="no-referrer"`. Left-click opens the article in the reader; modified/middle click opens the original URL in a new tab.
- `LIB-VIEW-1`: CSS responsive layout: wide = 3 columns (sidebar, list, reader); medium = sidebar + (list or reader); narrow = single column with no separate top bar: the list heading starts with `切换导航` (opens the sidebar as a drawer, focusing the drawer panel; closing returns focus to `切换导航`), and the reader shows only its own toolbar. On medium/wide desktop screens (`md+`), the left sidebar can be collapsed (`收起侧边栏` in the brand bar) and re-expanded (`展开侧边栏` in the list heading), persisted in `localStorage` (`reader.sidebarCollapsed`). Both the desktop sidebar collapse/expand and the narrow-screen drawer animate with 200 ms transitions. When the active article changes, the virtual list automatically scrolls to its row if its ID is in the active list, even if the row still shows a skeleton. Focus moves safely when a panel hides. Narrow-screen icon controls are at least 40 px; on touch (coarse-pointer) devices the whole UI scales up uniformly (root font size `112.5%`, so text, spacing, controls, icons, and article text grow together at every view-options tier) instead of enlarging individual controls; touch screens always show the read-row hollow circle; layouts pad for device safe areas; toasts span the bottom and dialogs open as bottom sheets below 640 px.
- `LIB-KEY-1`: There are no keyboard shortcuts in the library screen or reader (no `j`/`k`/`m`/`s`/`f`/`v`/`o`/`u`/`[`/`?`, no `Esc` to close an article, no shortcuts dialog); only dialogs, menus, and the image lightbox handle their own `Escape`.
- `LIB-TOAST-1`: At most one toast at a time (bottom-end), auto-dismissed after 6 s or on clicking `关闭`.
- `LIB-LINK-1`: Stored and API URLs with an invalid port are rejected on read/decode (a response containing one fails to decode). Every write path validates URLs, so such rows cannot be created through the app. Source links and modified/middle-click on rows and `在新页面打开源网页` only act on URLs the browser can parse; for URLs the server accepts that the browser cannot parse (e.g. scoped IPv6 hosts), source links render as plain text (no link) and open-in-new-tab shows a toast `无法在浏览器中打开此链接`, without invalidating the rest of a list response.
- `LIB-FOCUS-1`: When a dialog opened from a menu item closes, focus returns to the previously focused element, then to the menu trigger (recorded only for items that open a dialog, valid for the same task), and finally to the `main` landmark when neither is connected and focusable.

## Interface & Messages

- **Sidebar**: brand icon + `Lantern` + desktop `收起侧边栏` button + menu (`设置`, `视图选项` sub-panel identical to the reader's (`RD-APPEAR-1`, including `主题`), `语言：中文 / English`, `退出登录`; no keyboard-shortcuts item), `稍后阅读`, `全部订阅`, and `订阅源` section (header `+` button opens `新增 RSS 订阅` directly; folders are created only from a feed's `移动到` sub-panel (`新建目录`); header `⋮` menu: `导入…`, `导出…`, no unread filter); feed rows show the feed's site icon. The selected scope row is filled with the accent surface; unread counts are plain muted numbers. Every scope row swaps its unread count for a `⋯` menu (`全部标记为已读`, plus scope-specific actions; no `只显示未读`) on hover/focus, identically on touch and narrow screens.
- **Narrow screens (`< 768px`)**: the list heading's navigation toggle uses the sidebar icon and opens the sidebar as a 16.5rem drawer with rounded right corners over a dimmed backdrop.
- **List heading**: `展开侧边栏` (when the desktop sidebar is collapsed) + scope title + plain muted unread count on left; 1-click `只显示未读` toggle button (highlighted when active) + `将以上文章标为已读` + `⋯` menu (`全部标记为已读`, plus scope-specific items; the unread filter is only the toggle button, never a menu item) on right.

- `LIB-GROUP-1`: In `全部订阅` and folder lists, show a feed separator above the card or skeleton for the first ID of each contiguous run of the same feed in the active snapshot. Get the title and icon from sidebar feeds and show them only in the separator. If the first ID is removed, the separator moves to the next ID in the run.

| Situation | Text |
| --- | --- |
| loading / error / retry | `正在加载文章…` / `暂时无法加载文章` `请点击上方重试。` / `重试` |
| unread filter empty / action | `没有未读文章` `所有文章都已读过了。` / `查看全部文章` |
| list tools & menu | `将以上文章标为已读` / `只显示未读` / `全部标记为已读` |
| toast dismiss | `关闭` |
| open original link the browser cannot parse (`LIB-LINK-1`) | `无法在浏览器中打开此链接` |

## Acceptance

```gherkin
Feature: Library screen behavior
  Scenario: Marking read under the unread filter keeps the row until the list updates
    Given the unread filter is active on "全部订阅" (the default)
    When I open an unread article or toggle its read button
    Then the row stays visible as read and unread counts decrease by 1
    When I switch to "稍后阅读" and return to "全部订阅"
    Then the read article is no longer in the list

  Scenario: A background article appears without moving the visible article
    Given I have scrolled down the active list
    And the server has added an article above the first visible row
    When a live replacement succeeds
    Then the new article appears in server order
    And the first visible article remains at the same viewport offset

  Scenario: A live replacement removes a read row under the unread filter
    Given the unread filter is active and I have opened an unread article
    And the server has recorded the article as read
    When a live replacement succeeds
    Then the row disappears from the list
    And the article stays open with previous and next navigation disabled

  Scenario: Failed mark-all changes nothing and shows a toast
    Given the active list has 5 unread article IDs and the scope has an unread count of 9
    When "全部标记为已读" fails on the server
    Then the 5 rows stay unread, the counts stay at 9, and an error toast appears
```
