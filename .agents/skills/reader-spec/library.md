# The Library Screen

The single authenticated workspace: sidebar of scopes, virtualized article list, and reader pane.

## Rules

- `LIB-SCOPE-1`: Shows one scope at a time (`稍后阅读`, `全部订阅`, one folder, or one feed). Selecting the already-selected scope closes any open article without reloading the list.
- `LIB-LIST-1`: Each list load fetches one ordered ID snapshot (`CM-PAGE-1`), queues its IDs, and fetches the first batch. Scrolling within 600 px of the end fetches the next 30 queued IDs with at most one batch request in flight for the active snapshot. Append returned rows in queue order and drop missing IDs only after a successful batch. Keep consuming chunks until at least one visible row is added, the queue is exhausted, a request fails, or the list reloads. A failed batch keeps loaded rows and its queued IDs and shows `重试`, even when no rows have loaded.
- `LIB-RELOAD-1`: Fetch a fresh snapshot when entering the library, switching scope, toggling the unread filter (`?all`), changing the active single feed’s `从旧到新` setting (`FD-PREF-1`), or `全部标记为已读` settling as described in `LIB-READ-2`. Ordinary single-feed reloads omit the `order` query and use the feed’s stored order. There is no manual refresh action for normal feeds, in any menu. Discard stale snapshot and batch responses from earlier list loads. Entering the library or switching scope also refreshes sidebar feeds, folders, and unread counts.
- `LIB-FILTER-1`: Marking an item read never removes its row from the currently loaded list (even with the unread filter active); it stays shown as read until the next list reload.
- `LIB-READ-1`: Single read toggles, auto-read on open (`RD-READ-1`), and `将已加载文章标为已读` apply optimistically through one serial read queue. Each intent carries an explicit `read` value. Intents for one article coalesce while a request is in flight: toggles made meanwhile send only the latest value, and nothing is sent when it equals the confirmed value. An article never has two writes in flight. A row shows its latest intent. On failure, a row whose latest intent is still the failed value rolls back to its last server-confirmed state with its unread count, and one error toast appears per failed request batch; a failure the user has already superseded changes nothing and shows no toast. Ambiguous failures (no HTTP response) re-fetch the affected rows once after the queue drains.
- `LIB-READ-2`: `将已加载文章标为已读` marks the loaded unread rows of the active list through the read queue (sent as ID batches of up to 200). `全部标记为已读` calls the scope's own mark-all endpoint (`later.md`, `feeds.md`, `folders.md`) with a `before` UUIDv7 boundary and marks only rows at or below it; newer rows and their later toggles are unaffected. It is pessimistic: a barrier in the same queue that runs after earlier read intents and holds later ones until it settles. Nothing changes on screen until the server answers; while pending, the list heading and the scope's sidebar row show a spinner. Its boundary is taken at click time: the accepted snapshot's `boundary` when the marked scope is active and its snapshot is available, else the scope's last applied unread-count boundary, else the count endpoint is fetched when the barrier runs, without applying sidebar counts. A boundary-fetch failure or a definite request failure (HTTP error) shows one error toast and changes nothing. On success or an ambiguous failure (no HTTP response, no toast), the active list fetches a fresh snapshot whatever scope was marked (when a library page is mounted), the open article refreshes in place if it belongs to the marked scope (not reopened or auto-marked), and sidebar counts refresh once after the read queue drains (or once directly when no library page is mounted). After an ambiguous mark-all, later toggles on covered rows are sent rather than assumed already applied. Folder membership is evaluated when the read-all executes. If the session ends while a mark-all is pending, nothing more is sent and no toast or change happens. Neither button is ever disabled, and the `全部标记为已读` menu item is never disabled.
- `LIB-COUNT-1`: Sidebar hides zero unread counts; list heading always shows the count. Folder count = sum of its feeds' counts; `全部订阅` count = sum of all feeds' counts.
- `LIB-COUNT-2`: Sidebar unread counts (feed counts and saved-page count, each with its `boundary`) refresh on the existing sidebar triggers (`LIB-RELOAD-1` and mutations), after each read-queue drain, and every 60 s while the library is mounted. The 60 s timer is skipped while the read queue is non-empty, pauses while the page is hidden, and restarts after a refresh that applies counts. Becoming visible refreshes immediately. A count response applies only if the queue was idle when it was sent and no read or mark-all was enqueued before it returned; otherwise a refresh runs on drain. A count field changed locally during the request keeps its local value. Count refreshes never reload lists.
- `LIB-ROW-1`: Each row is a rounded card showing, left to right: an independent leading read-toggle control (`aria-pressed`; solid dot when unread, hollow circle on hover/focus when read), then source line (site icon + feed title for feed items / URL hostname for saved pages, relative publish time right-aligned when present, refreshing each wall-clock minute while the library is mounted, pausing while the page is hidden, and refreshing immediately when the page becomes visible; in `全部订阅` and folder lists the icon and feed title move to the group separator (`LIB-GROUP-1`), the line keeps only the publish time and is omitted when there is none; the single-feed list shows the feed title without icon), title (max 3 lines; bold when unread, dimmed when read), summary plain text (fixed max 3 lines, not configurable; no thumbnail). Feed icons (sidebar, rows, feed options) are the feed's own image (`iconUrl`: RSS channel `<image><url>`, Atom `icon` then `logo`, JSON Feed `favicon` then `icon`; absolute http(s) only, resolved against the feed URL, stored on refresh and returned as `iconUrl`), falling back to the `/favicon.ico` of the feed's site origin (`siteUrl`, `FD-PARSE-6`; never derived from the feed URL's host), then the RSS glyph (each step used when the previous is absent or fails to load); saved pages use the page origin's `/favicon.ico`, then a generic icon. Images load directly in the browser with `referrerpolicy="no-referrer"`. Left-click opens the article in the reader; modified/middle click opens the original URL in a new tab.
- `LIB-VIEW-1`: CSS responsive layout: wide = 3 columns (sidebar, list, reader); medium = sidebar + (list or reader); narrow = single column with no separate top bar: the list heading starts with `切换导航` (opens the sidebar as a drawer, focusing the drawer panel; closing returns focus to `切换导航`), and the reader shows only its own toolbar. On medium/wide desktop screens (`md+`), the left sidebar can be collapsed (`收起侧边栏` in the brand bar) and re-expanded (`展开侧边栏` in the list heading), persisted in `localStorage` (`reader.sidebarCollapsed`). Both the desktop sidebar collapse/expand and the narrow-screen drawer animate with 200 ms transitions. When the active article changes, the virtual list automatically scrolls to keep the selected row in view. Focus moves safely when a panel hides. Narrow-screen icon controls are at least 40 px; on touch (coarse-pointer) devices the whole UI scales up uniformly (root font size `112.5%`, so text, spacing, controls, icons, and article text grow together at every view-options tier) instead of enlarging individual controls; touch screens always show the read-row hollow circle; layouts pad for device safe areas; toasts span the bottom and dialogs open as bottom sheets below 640 px.
- `LIB-KEY-1`: There are no keyboard shortcuts in the library screen or reader (no `j`/`k`/`m`/`s`/`f`/`v`/`o`/`u`/`[`/`?`, no `Esc` to close an article, no shortcuts dialog); only dialogs, menus, and the image lightbox handle their own `Escape`.
- `LIB-TOAST-1`: At most one toast at a time (bottom-end), auto-dismissed after 6 s or on clicking `关闭`.
- `LIB-LINK-1`: Stored and API URLs with an invalid port are rejected on read/decode (a response containing one fails to decode). Every write path validates URLs, so such rows cannot be created through the app. Source links and modified/middle-click on rows and `在新页面打开源网页` only act on URLs the browser can parse; for URLs the server accepts that the browser cannot parse (e.g. scoped IPv6 hosts), source links render as plain text (no link) and open-in-new-tab shows a toast `无法在浏览器中打开此链接`, without invalidating the rest of a list response.
- `LIB-FOCUS-1`: When a dialog opened from a menu item closes, focus returns to the previously focused element, then to the menu trigger (recorded only for items that open a dialog, valid for the same task), and finally to the `main` landmark when neither is connected and focusable.

## Interface & Messages

- **Sidebar**: brand icon + `Lantern` + desktop `收起侧边栏` button + menu (`设置`, `视图选项` sub-panel identical to the reader's (`RD-APPEAR-1`, including `主题`), `语言：中文 / English`, `退出登录`; no keyboard-shortcuts item), `稍后阅读`, `全部订阅`, and `订阅源` section (header `+` button opens `新增 RSS 订阅` directly; folders are created only from a feed's `移动到` sub-panel (`新建目录`); header `⋮` menu: `导入…`, `导出…`, no unread filter); feed rows show the feed's site icon. The selected scope row is filled with the accent surface; unread counts are plain muted numbers. Every scope row swaps its unread count for a `⋯` menu (`全部标记为已读`, plus scope-specific actions; no `只显示未读`) on hover/focus, identically on touch and narrow screens.
- **Narrow screens (`< 768px`)**: the list heading's navigation toggle uses the sidebar icon and opens the sidebar as a 16.5rem drawer with rounded right corners over a dimmed backdrop.
- **List heading**: `展开侧边栏` (when the desktop sidebar is collapsed) + scope title + plain muted unread count on left; 1-click `只显示未读` toggle button (highlighted when active) + `将已加载文章标为已读` + `⋯` menu (`全部标记为已读`, plus scope-specific items; the unread filter is only the toggle button, never a menu item) on right.

- `LIB-GROUP-1`: In `全部订阅` and folder lists, show a feed separator (feed icon + feed title) above the card inside the first loaded row of each feed group; cards in these lists do not repeat the feed icon or title. Use the current title and icon from sidebar feeds. Recompute which row shows the separator when the group’s first ID is dropped.

| Situation | Text |
| --- | --- |
| loading / error / retry | `正在加载文章…` / `暂时无法加载文章` `请点击上方重试。` / `重试` |
| unread filter empty / action | `没有未读文章` `所有文章都已读过了。` / `查看全部文章` |
| list tools & menu | `将已加载文章标为已读` / `只显示未读` / `全部标记为已读` |
| toast dismiss | `关闭` |
| open original link the browser cannot parse (`LIB-LINK-1`) | `无法在浏览器中打开此链接` |

## Acceptance

```gherkin
Feature: Library screen behavior
  Scenario: Marking read under unread filter keeps the row until reload
    Given the unread filter is active on "全部订阅" (the default)
    When I open an unread article or toggle its read button
    Then the row stays visible as read and unread counts decrease by 1
    When I switch to "稍后阅读" and return to "全部订阅"
    Then the read article is no longer in the list

  Scenario: Failed mark-all changes nothing and shows a toast
    Given a scope has 5 loaded unread rows and total count 9
    When "全部标记为已读" fails on the server
    Then the 5 rows stay unread, the counts stay at 9, and an error toast appears
```
